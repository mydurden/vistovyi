# ZS-150: вкладка unit у lead — порожня / «не editable» — факт (без правок)

**Автор:** lead обрав підрозділ (на фото — **0/0** о/с) і хоче **правити звіт unit у цьому вікні**. Prefs і код доступу — не причина.  
**Не про** підпис «Мережа не відповіла…» (той catch-all — окремий контур sync).  
**База:** `main` @ `2abd21c`, SW **`vistovyi-v62`**. Лише фіксація; змін у коді немає.  
**Фото:** `f09a4569-c7a2-4ad3-b60d-4965ffe69701.png` (у середовищі агента файл не змонтувався; зміст з опису автора: обраний підрозділ, особовий склад 0/0).

## Що робить lead, коли обирає підрозділ

У перемикачі звіту (`#report-switch`) пункт unit має `data-open-unit` / `data-pick-value` (~5209–5231). Коментар у коді:

> Статус («Відсутній звіт» тощо) лишається візуально; **вкладку не блокуємо**.

Далі `openReportChoice` / клік `data-open-unit` (~3949–3962, ~11239–11247):

1. `applyCode(unitCode)` → `scope === "all"`, `openCode = unit`, `holder = назва`;
2. `activateReport(unitCode)`;
3. `reportRoot` лишається lead (корінь видавця);
4. `save()` + `render()`.

Тобто вікно — це **окремий живий звіт** з `reportKey === код unit`, не «фільтр» загального.

## Чому на екрані 0/0 (порожня вкладка)

`activateReport` (~4516–4567):

| Стан `bundles[unitCode]` | Що стає live |
|--------------------------|--------------|
| є збережений bundle (після успішного ingest з Диска / локальних правок) | піднімає його в `state.report` / cards |
| **немає** | `freshOverlays()` + **`emptyUnitReport(unit)`** → `people: []`, `machines: []`, `tasks: []` |

`emptyUnitReport` (~4262–4274) — навмисно порожній каркас з назвою/кодом unit. UI (`renderPeople` → `peopleStats`) малює **0/0**.

Звідки вміст **не** береться при відкритті вкладки:

1. **Не з «Загальний звіт».** Люди, уже злиті в lead через `mergeUnitIntoGeneral` (префікс id), лежать у `bundles[lead]`. Перемикач на unit **не** розбирає загальний назад у вкладку.
2. **Не з Drive синхронно в `activateReport`.** Читання unit-файлу — лише в `syncChildUnits` (`decryptWithCode(unit.code, …)` → `ingestChildUnit` → за наявності відкритої вкладки `applyOpenUnitFromBundle`). Поки sync не поклав bundle, вкладка лишається порожньою оболонкою.
3. Після reload (див. ZS-149) `applyCode` може ще й **затерти** `zvitnist.cache.v1` до restore — тоді навіть локальний знімок unit не піднімається.

Типовий рядок у списку перемикача: статус **«Відсутній звіт»** (`unitReportStatus` → `missing`, ~3884–3894) — sync не отримав/не розшифрував файл unit. Вкладку відкрити можна, але **live = empty**.

Prefs/код lead тут ні при чому: перемикач і порожній каркас працюють і з валідними prefs.

## Чому це виглядає як «не editable»

У **vistovyi-v62** вкладка unit для lead з `scope === "all"` **не** read-only у сенсі UI-замка:

- `canDelete()` → `true` (~3804–3806) → є «+» / копія дня / олівець на картках (`sectionTools`, ~4983–4988);
- статус «Відсутній звіт» **не** блокує вибір (~5228–5230).

Але для автора «правити звіт unit» = працювати з **даними ланки**. При 0/0:

- немає карток о/с/ОВТ з файлу unit — немає що відкрити олівцем;
- видно порожній звіт з назвою підрозділу, ніби ланка ще без штату;
- очікуваний штат (з телефону unit / з уже злитого загального) **у цьому вікні не з’являється**, бо інший bundle і немає успішного ingest.

Тобто «не editable» у спостереженні автора — **порожня оболонка без змісту unit-звіту**, не `is-locked` на всю вкладку і не зламані prefs.

Локально «+» теоретично додає в цей порожній live; на Диск unit піде лише через sync з `driveChildWriteCode()` і ім’ям файлу від канонічної назви. Це вже наступний крок після того, як вкладка взагалі покаже/тримає дані — зараз факт саме про **порожнє вікно після вибору підрозділу**.

## Висновок (факт)

На **vistovyi-v62**, коли lead обирає підрозділ у перемикачі:

1. Відкривається окремий `activateReport(unit)` → без `bundles[unit]` це **`emptyUnitReport` → 0/0**.
2. Вміст unit у це вікно не підтягується з загального і не з Диска в момент кліку — лише після успішного sync/ingest (ключ файлу = **`unit.code`**).
3. Вкладку код **не блокує**; «не editable» = немає змісту звіту unit (часто ще й статус «Відсутній звіт»), а не заборона prefs/коду.
